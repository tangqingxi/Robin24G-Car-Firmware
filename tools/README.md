# 六轴传感器串口监视（0x26 0x9A 波形帧）

台架用：**四个电机不接、不接遥控器、不进入解锁流程**，上电即从 UART 持续输出
六轴数据 + 时间戳，电脑端实时画曲线并存 CSV。

本目录有两个工具，共用一个纯标准库的协议模块 `uart_proto.py`：

| 文件 | 作用 |
|---|---|
| `uart_sensor_monitor.py` | 实时曲线 + 六轴 CSV + 性能统计 CSV（0x269A / 0x269B） |
| `accel_six_face_cal.py` | **加速度计六面校准**（命令行交互，见第 8 节） |
| `imu_axis_map.py` | **传感器轴 → 机体系 FRD 映射确认**（见第 9 节） |
| `uart_proto.py` | 两种帧的解析/组帧（无绘图依赖，三个工具共用） |

---

## 1. 为什么用这个报文

现有 UART 上有三种报文可复用：

| 报文 | 帧头 | 长度 | 现有用途 | 是否适合本任务 |
|---|---|---|---|---|
| 匿名上位机帧 | `0x88 0xAF` | 32 B | 飞控显示（欧拉角，无时间戳） | 否：没有时间戳/标志位，且受匿名协议固定缩放约束 |
| 高速调试帧 | `0x26 0x99` | 21 B | 飞行调试（pitch/thrust/速度估计…） | 否：负载被飞控通道占满，改成六轴会破坏原调试视图 |
| **六轴波形帧（新增）** | `0x26 0x9A` | 27 B | **台架传感器观察** | **是**：带 4 字节时间戳、零偏、标志位，帧结构复用 0x2699 的成帧/校验/DMA 通道 |

新帧沿用 `0x2699` 的成帧方式（0x26 帧头、seq、累加和校验）和同一条
`UartDbgSend()` 非阻塞 DMA 通道，**只增加一个功能字 0x9A**，不改动旧报文。

## 2. 帧格式（27 字节，多字节字段一律大端）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `0x26` | 帧头 1 |
| 1 | 1 | `0x9A` | 帧头 2 |
| 2 | 1 | `seq` | 帧序号 0~255 循环，掉帧可见跳变 |
| 3 | 4 | `t_ms` | 上电后毫秒数（u32，约 49.7 天回绕） |
| 7 | 2 | `ax` | 加速度 X，s16，**2048 LSB/g**（±16g） |
| 9 | 2 | `ay` | 加速度 Y |
| 11 | 2 | `az` | 加速度 Z |
| 13 | 2 | `gx` | 角速度 X，s16，**16.4 LSB/dps**（±2000dps） |
| 15 | 2 | `gy` | 角速度 Y |
| 17 | 2 | `gz` | 角速度 Z |
| 19 | 2 | `bx` | 陀螺零偏 X（原始 LSB，未从 gx 扣除） |
| 21 | 2 | `by` | 陀螺零偏 Y |
| 23 | 2 | `bz` | 陀螺零偏 Z |
| 25 | 1 | `flags` | 见下 |
| 26 | 1 | `chk` | `sum(byte[2..25]) & 0xFF` |

`flags` 位定义：

| 位 | 含义 |
|---|---|
| bit0 | 数据经过 **5 点中值滤波**（当前恒为 1） |
| bit1 | 帧内陀螺**已扣零偏**（当前恒为 0） |
| bit2 | 陀螺零偏**已标定**（bx/by/bz 有效） |
| bit3 | 已解锁（电机断开时不接遥控器，一般恒为 0） |
| bit4~7 | 保留 |

**发送节奏**：控制节拍 200 Hz，每 2 拍发 1 帧 → **100 Hz**；
27 B × 100 Hz ≈ 2.7 kB/s，占 115200 波特率约 23%。

## 2.1 性能统计帧（0x26 0x9B，44 字节，约 1 Hz）

测量固件（`PERF_MEAS_EN=1`）在主循环里每秒发一帧，**不占用控制任务时间**。
字段全部大端，单位写在下表里：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `0x26` | 帧头 1 |
| 1 | 1 | `0x9B` | 帧头 2 |
| 2 | 1 | `ver` | 协议版本 = 1 |
| 3 | 1 | `seq` | 帧序号 0~255（跳变 = 漏帧） |
| 4 | 4 | `build_id` | 固件构建标识（本次 0x20261119） |
| 8 | 2 | `window_ms` | 本窗口长度 ms |
| 10 | 2 | `task_cnt` | 窗口内控制任务调用次数 |
| 12 | 2 | `task_avg_us` | 控制任务平均耗时 µs（墙钟，含中断/等待） |
| 14 | 4 | `task_max_us` | 控制任务最大耗时 µs |
| 18 | 2 | `imu_cnt` | 窗口内 IMU 区间调用次数 |
| 20 | 2 | `imu_avg_us` | IIC 读 6 轴 + 5 点中值滤波平均耗时 µs |
| 22 | 4 | `imu_max_us` | 同上最大耗时 µs |
| 26 | 4 | `late_max_us` | 最大启动迟到 µs（计划启动 → 实际启动） |
| 30 | 2 | `int_min_us` | 相邻两轮实际启动间隔最小值 µs |
| 32 | 2 | `int_max_us` | 相邻两轮实际启动间隔最大值 µs |
| 34 | 2 | `miss_win` | 本窗口截止违约次数（计划启动→返回 > 5000 µs） |
| 36 | 4 | `miss_total` | **上电累计**截止违约次数（不受串口漏帧影响） |
| 40 | 2 | `drop_total` | 统计帧发送丢弃累计次数（TX 忙时丢弃） |
| 42 | 1 | 保留 | 0 |
| 43 | 1 | `chk` | `sum(byte[2..42]) & 0xFF` |

**口径提醒**：`task_avg_us` 是墙钟时间，包含任务执行期间的中断和等待；`imu_*` 已包含在
`task_*` 里，**两者不能相加**当作 CPU 占用；首次连接遥控器等偶发长延迟会保留在最大
值里，分析时应先按时间段区分。

## 3. 数据到底"滤了没有、扣了没有"

| 问题 | 回答 |
|---|---|
| 是否滤波 | **是**。数据是控制环本拍实际使用的 `accel[]/gyro[]`，已经过 `t3488_data_filter_handler()` 的 **5 点滑动中值滤波**（每 5 ms 采样一次，窗口 25 ms） |
| 是否扣零偏（加速度） | **否**。固件对加速度计不做零偏、不做标度修正，只做 atan2 姿态反推 |
| 是否扣零偏（陀螺） | **帧内不扣**。`gx/gy/gz` 是原始 LSB；零偏只在 `update_euler_dt()` 内部扣除。零点 `bx/by/bz` 随帧下发，CSV 里同时给出 `gx_c_dps` 等"已扣零偏"列，可直接对比 |
| 零偏什么时候有值 | 只有遥控器**首次连上**（`car_work()` → `get_GyroSensor_offset()`）或做了水平校准组合后才标定。**不接遥控器的台架场景下零偏为 0、`flags.bit2=0`**，此时 `gx_c_dps` 与 `gx_dps` 相同 |
| 有没有高通/低通 | 除 5 点中值外，控制环内的低通/互补滤波**不会**改到本帧数据（本帧取的是滤波后、进姿态解算前的值） |

## 4. 接线

| 板子 | 方向 | USB-TTL |
|---|---|---|
| `PB0`（Isen2，UART0 TX） | → | RXD |
| `PB1`（Isen1，UART0 RX） | ← | TXD（只收数据可不接） |
| GND | — | GND |

- 波特率 **115200**，8 数据位，无校验，1 停止位。
- 上电即可发数据，不需要解锁、不需要遥控器。
- `PB0/PB1` 同时是电流采样（Isen）引脚，但 `OverCurrentHandler()` 当前是注释掉的，
  运行时不采样，不会和 UART 抢引脚。
- 黑匣子 UART 读出（特技键）与本报文共用发送缓冲，读出期间本帧会自动暂停，
  两者不要同时使用。

## 5. 电脑端

```bash
python -m pip install pyserial numpy matplotlib

# 查看串口
python uart_sensor_monitor.py --list

# 实时曲线 + CSV（默认自动挑 USB-TTL 串口，窗口 10s）
python uart_sensor_monitor.py --port COM3

# 只记 CSV，不画图（长时间采集）
python uart_sensor_monitor.py --port COM3 --no-plot --duration 120 --csv bench.csv
```

参数：

| 参数 | 说明 |
|---|---|
| `--port` | 串口号，省略则自动选（CH340/CP210/FT232…） |
| `--baud` | 默认 115200 |
| `--csv` | 六轴 CSV 保存路径，默认 `uart_sensor_年月日_时分秒.csv` |
| `--stats-csv` | 性能统计 CSV 路径，默认在六轴 CSV 名后加 `_perf` |
| `--window` | 曲线时间窗（秒），默认 10 |
| `--no-plot` | 不画图，只写 CSV |
| `--duration` | 采集多少秒后自动退出（0 = 一直采） |
| `--simulate` | 用模拟数据源代替串口（无硬件自测界面/退出/CSV） |
| `--acc-lsb-per-g` | 默认 2048（±16g） |
| `--gyro-lsb-per-dps` | 默认 16.4（±2000dps） |

**一次运行同时产出两个文件**：

- 六轴：`<csv>`，100 Hz，21 列；
- 性能：`<csv 同名>_perf.csv`，约 1 Hz，17 列（列名带单位，窗口值/累计值分开）。

收到性能帧时控制台会打印一行 `[性能] seq=… 任务 平均/最大 … 超期…`；
**看不到这一行说明没有收到 0x269B 统计帧**（固件不是测量版，或 `PERF_MEAS_EN=0`）。

### 界面操作

| 操作 | 作用 |
|---|---|
| **F** | 开/关"跟随最新数据"。拖动/缩放曲线会自动关闭跟随，画面冻结便于查看；按 F 恢复 |
| **Q** 或点右上角 ✕ | 结束采集：先停界面临时器，再让采集线程收尾，CSV 落盘后退出 |

- x 轴刻度固定为 `-窗口 ~ 0`（0 = 当前时刻），数据从右往左滚动；
- 曲线刷新约 10 Hz（`PLOT_PERIOD_MS=80`），**接收与 CSV 仍是 100 Hz 全量**；
- 状态栏（图窗底部）显示：跟随状态、累计帧数、实测速率、校验错/丢帧、零偏、数据标志。

### 线程模型（为什么界面卡不影响数据）

```
采集线程：串口 read → 组帧校验 → 逐帧写 CSV → 帧放进有界队列(2000)
主线程  ：Tk 定时器每 80ms 取走队列 → 追加到绘图缓冲 → blit 重画曲线
```

- CSV 由采集线程直接写，**不经过界面**，所以界面再忙也不会丢 100 Hz 数据；
- 队列满时丢的是"绘图用"的旧帧，CSV 已落盘不受影响；
- 拖动/缩放期间跳过重画，只收数据；空闲（无数据/冻结）时定时器空转，窗口照常响应。

### 重画策略（为什么不会重影）

- 曲线和状态栏都设成 `animated=True`：整图重画时它们**不参与**，所以缓存下来的
  背景位图里没有动态内容，永远不会把"带曲线的画面"当成背景；
- 量程变化 / 窗口缩放 / 布局变化 → `fig.canvas.draw()` 完整静态重绘（坐标框外的旧
  刻度、旧轴标签一并清掉）→ 重新缓存干净背景 → 再补画曲线和状态栏；
- 平时只做"恢复子图背景 + 补画曲线 + blit 子图区域"，状态栏区域不动；
- 状态栏约 1 Hz 更新一次，更新时整图恢复背景再重画文字，文字变短也不会留旧字；
- 图例放在坐标框**上方**（框外），曲线被裁剪在框内，不会压到图例。

CSV 列（21 列，UTF-8 BOM，Excel 可直接打开）：

```
t_ms, seq, ax_lsb, ay_lsb, az_lsb, gx_lsb, gy_lsb, gz_lsb,
bx_lsb, by_lsb, bz_lsb, ax_g, ay_g, az_g,
gx_dps, gy_dps, gz_dps, gx_c_dps, gy_c_dps, gz_c_dps, flags
```

- `*_lsb`：设备原始整数（未做任何换算）
- `*_g` / `*_dps`：按灵敏度换算后的物理量
- `*_c_dps`：`(glsb - bias_lsb) / 16.4`，即"已扣零偏"的角速度
- `flags`：十进制，按位对照第 2 节

## 6. 常见问题

| 现象 | 排查 |
|---|---|
| 收不到任何帧 | 确认 TX/RX 是否交叉、波特率 115200、共地；`--list` 看串口是否选对 |
| 有数据但校验错很多 | 波特率不对 / 线太长 / 电源干扰；可降低到 57600 试（固件需同步改） |
| 帧率只有 ~50 Hz | 说明 `FC_SENSOR_DBG_DIV` 被改成 4，或控制节拍被阻塞 |
| `零偏未标定` | 正常：无遥控器场景不会执行零偏标定；需要零偏时接遥控器第一次连上即可 |
| 静止时 `ax/ay` 不为 0、`az` 不接近 1 g | 属于安装倾角/加计零偏，固件不做补偿，属预期 |
| 曲线全是 0 | 检查是否误开了 7.9 的 `FC_UART_DBG_EN`（会与本报文抢缓冲） |
| 没有 `[性能]` 行、`_perf.csv` 只有表头 | 固件不是测量版（`PERF_MEAS_EN=0`），或统计帧一直被丢弃（看 `drop_total`） |
| 性能帧 `seq` 跳变 | 串口丢帧（波特率/线长/干扰），`miss_total` 仍可靠（上电累计） |
| 状态栏中文是方块 | 系统里没有微软雅黑/黑体；脚本已按 雅黑→SimHei→Noto 兜底，也可自己装一个中文字体 |
| 拖动曲线后画面不动了 | 正常：拖动/缩放会自动关闭"跟随"，按 **F** 恢复实时刷新 |
| 关窗口后程序还在跑 | 旧版才会（采集在主循环里）；新版关窗即停采集线程并落盘 CSV |

## 8. 加速度计六面校准（accel_six_face_cal.py）

### 8.1 做什么

T-3488 的加速度原始计数有零偏和比例误差。虽然 0x269A 帧里的加速度已经过 **5 点中值
滤波**，但**没有做六面校准**——中值滤波只是去尖峰，零偏/比例误差还在。本工具把手持
飞机依次摆到 6 个静止姿态，自动识别、判稳、采样，最后算出：

```
offset_lsb = (P + N) / 2                     # 该轴正向/负向两面的平均计数
scale      = (2 * 2048) / (P - N)            # 以 1g = 2048 LSB 为基准
corrected_lsb = (raw_lsb - offset_lsb) * scale
```

标定以 **1g = 2048 LSB** 为基准。广州本地重力约 **9.788 m/s²**（标准 9.80665），
两者差 0.19%，对拟合没有影响；只在最后的模长验证时知道这件事即可。

### 8.2 前提

- 接线同监视器：飞机 TX → USB 串口 RX，共地，115200-8-N1；工具**只收不发**；
- 先关闭 `uart_sensor_monitor.py`（COM 口独占），电机断开，飞控保持上锁；
- 只接受未解锁的样本（`flags` 的 ARMED 位为 0），检测到解锁会拒绝采样。

### 8.3 操作

```powershell
cd "E:\泡沫纸飞机\code\tools"
python accel_six_face_cal.py --port COM3 --out accel_cal.json
```

- `--port` 改成本机串口；`--list` 先看有哪些；
- 顺序随意：+X/-X/+Y/-Y/+Z/-Z 依次摆好，每面**停稳约 1.5 s**（状态行会显示 `请停稳 1.5/1.5s`），
  之后自动**采样 5 s**（`正在采样 …`）；
- 工具实时显示：当前姿态、三轴读数(g)、状态、还缺哪些面；
- 重复摆到已完成的面会提示"请翻到未完成的面"；
- 采样中晃动、姿态改变、丢帧 → 本面作废并提示重采；
- 六面齐全后写出 JSON 并打印"修正前 / 修正后"的模长摘要。

### 8.4 阈值（都在 `accel_six_face_cal.py` 顶部的 `CONFIG`）

| 键 | 默认 | 含义 |
|---|---|---|
| `stable_sec` | 1.5 s | 判定静止所需的连续稳定时长 |
| `sample_sec` | 5.0 s | 每面采样时长 |
| `min_samples` | 200 | 采样点数下限 |
| `main_min_g` / `main_max_g` | 0.90 / 1.10 | 主轴分量允许范围 |
| `cross_max_g` | 0.25 | 另外两轴分量上限（判"摆正"） |
| `accel_std_max_g` | 0.02 | 静止判定：三轴加速度标准差上限 |
| `gyro_max_dps` | 5.0 | 静止判定：三轴角速度上限（防匀速转动） |
| `max_gap_s` | 0.10 | 相邻帧最大间隔，超过按丢帧处理 |
| `span_min_lsb` / `span_max_lsb` | 3400 / 4800 | 正负面跨度合理范围（名义 4096） |

手抖得厉害就调大 `accel_std_max_g` / `gyro_max_dps`；摆得不够平就调大 `cross_max_g`。
**不建议把 `stable_sec`/`sample_sec` 调得很小**，噪声会让零偏估计变差。
也可以用命令行临时改：`--stable 2.0 --sample 8.0`。

### 8.6 怎么判断结果可信

- 六面拟合是"用这 6 个面解 6 个未知量"，拟合残差小只说明**自洽**，不等于任意姿态都准；
- 独立验证：把飞机**另外摆几种静止斜放姿态**（比如 30°、45°），用修正后的三轴读数算
  模长，应该在 **1.000 ± 0.005 g** 内；偏大/偏小说明某轴 scale 不对，某个面没摆正；
- 某个轴跨度检查不通过（`span` 超出 3400~4800 LSB）时，工具会把该轴的正负面作废并
  要求重采；按提示重新摆这两个面即可。

### 8.7 常见问题

| 现象 | 处理 |
|---|---|
| 打开串口失败 | 先关掉监视器 / 其他串口工具，确认 COM 号 |
| 状态行一直"请停稳" | 手没停稳或摆得不平；看提示里的"横向分量"是多少 |
| 一直提示"姿态接近 +X，但机身仍倾斜" | 调到该面水平（可用垫块/桌面） |
| 采到一半提示"重新采" | 采样中动了或丢帧；停稳后重新保持该面即可 |
| 收不到任何数据 | 固件不是测量版/没有六轴帧；先用监视器确认能看到 100Hz 数据 |

### 8.8 单面补测（--resume / --face）

六面里只有某一面没采好时，不用六面重来：加载已有校准 JSON，只重采这一面，
其余五面原样保留，合并后重新求解。

```powershell
Set-Location "E:\泡沫纸飞机\code\tools"
python accel_six_face_cal.py --port COM12 --resume "..\data\accel_cal.json" --face=-Z --out "..\data\accel_cal_retest.json"
```

- **负号面必须写成 `--face=-Z`**（等号形式）：写成 `--face -Z` 时 argparse 会把 `-Z`
  当成选项而报错；
- `--face` 的六个取值就是 **UART 原始读数**的面：`-Z` 表示传感器 `az ≈ -1g`
  （本机倒放就是这一面）。它与机体系 FRD 的轴/符号无关，本工具**不读取**映射文件；
- 打开串口之前先校验输入 JSON：格式版本、传感器型号、量程、LSB/g、六面记录；
  任何一项不兼容都会打印原因并退出，不会打开串口，也不会改动任何文件；
- 采集规则与六面模式相同（默认 1.5 s 判稳 + 5 s 采样），并且**只接受目标面**：
  摆到别的面会提示"当前是 +Y，本工具只补测 -Z"，状态行同时显示目标面、当前面、
  XYZ、两条横向分量和进度；
- 换面、晃动、解锁、帧序跳变或时间戳异常都会**清空判稳与采样窗口**，重新判稳；
- 结束前检查整段采样的波动，超阈值重新采本面；
- 成功后只替换目标面的记录，其余五面保持原均值/波动/样本数/时长，再用同一公式和
  跨度检查重新求解；输出到新文件（`--out` 省略时自动按时间戳命名，同名不覆盖），
  原 JSON 不动；
- 结束时会打印目标面的旧/新均值与标准差，以及受影响轴的旧/新 offset、跨度、scale，
  并列出另外两轴确认未变。注意这些是**拟合用数据**，最终精度仍要用静止斜放姿态验证。

## 9. 传感器轴 → 机体系 FRD 映射（imu_axis_map.py）

### 9.1 做什么

确认 T-3488 焊在板子上以后，传感器自身的 X/Y/Z 与机体系（右手 FRD：**+X 向前、
+Y 向右、+Z 向下**）是怎么对应的：哪根轴对哪根轴、要不要取反。

原理：静止时加速度计测的是**比力**，方向指向上方。把机体某个轴摆成朝下时，该 FRD 轴
的期望读数是 **-1g**。例如机体 +X 朝下时传感器 +Y 读数约 +1g，则 **X_frd = -Y_sensor**。

本工具**只做轴映射**：不读 `accel_cal.json`，不算零偏/比例系数（那些由第 8 节的
六面校准负责）。加速度计和陀螺仪各自校准完成后，共用这同一份安装映射。

### 9.2 六个实体摆法（按工具提示顺序，统一为"机体 ±轴朝下"）

| 顺序 | 姿态 | 摆法 |
|---|---|---|
| 1 | 机体 **+Z 朝下** | 正放：机腹朝下，机头朝前 |
| 2 | 机体 **+Y 朝下** | 右侧朝下：右机翼朝下，机身侧立 |
| 3 | 机体 **+X 朝下** | 机头朝下：机头垂直朝下，机尾朝上 |
| 4 | 机体 **-Z 朝下** | 倒放：机腹朝上，机背朝下 |
| 5 | 机体 **-Y 朝下** | 左侧朝下：左机翼朝下，机身侧立 |
| 6 | 机体 **-X 朝下** | 机尾朝下：机头垂直朝上，机尾朝下 |

> 姿态 ID（JSON 的 `poses` 键）沿用旧命名保证兼容：
> `Z_down`=+Z 朝下、`Y_down`=+Y 朝下、`X_down`=+X 朝下、
> `Z_up`=**-Z 朝下**、`Y_up`=**-Y 朝下**、`X_up`=**-X 朝下**。

每步工具会提示摆法，摆好后在电脑上按 **Enter**，它采样约 1.2 s（显示 XYZ 读数、当前
主轴与稳定进度）并记录均值。允许轻微倾斜（主轴 ≥0.5g 且明显大于另外两轴即可），
但晃动、主轴不明、数据间断、飞控解锁都会要求重采。

### 9.3 命令

```powershell
cd "E:\泡沫纸飞机\code\tools"
python imu_axis_map.py --port COM12 --out "..\imu_axis_map_frd.json"
```

`--port` 改成本机串口（`--list` 先看）；`--out` 省略时写到当前目录的
`imu_axis_map_frd.json`（同名不覆盖，自动加 `_1`）。`--window` 可改每姿态采样时长。

### 9.4 判定与校验

- 每个姿态取均值后看主轴（绝对值最大的分量）与符号；
- 同一个机体轴的两个姿态（如 **+Z 朝下** 与 **-Z 朝下**）必须落在**同一传感器轴**且**符号相反**；
- 三行三列各只有一个非零元素（0/±1），**行列式必须为 +1**（右手系）；
- 任何一项不通过：打印具体原因 → 只重采相关姿态（行列式/重复映射则全部重采），
  **不写出映射文件**。

```json

  "sensor": {"model": "T-3488", "accel_lsb_per_g": 2048.0},

工具同时会打印三条人能读懂的映射和 3×3 矩阵：

```

Z_frd = +Z_sensor

矩阵（v_frd = R × v_sensor；行 = FRD 的 X/Y/Z，列 = 传感器 X/Y/Z）：
  [+1   0   0]

### 9.6 注意

- 先关掉监视器/校准工具（COM 口独占）；电机断开、飞控保持上锁；
- 只接收 UART，**不向飞机发送任何指令**，也不需要垫块以外的任何工装；
- `det = -1` 说明某次摆法或读数有误（真实安装一定是右手系），按提示全部重采；
- 与零偏/比例的关系：先用本工具定轴映射，再用 `accel_six_face_cal.py` 定零偏与比例，
  最后按 `v_frd = R × ((raw - offset) * scale)` 使用（两者顺序可交换，都是线性变换）。
